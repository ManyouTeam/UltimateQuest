# 🎁 奖励配置

奖励决定玩家完成任务后得到什么。普通任务、周期委托、卷轴、战令等级和里程碑阶段使用同一套奖励格式，区别在于配置位置。

## 固定奖励配置示例

下面是奖励片段，可替换[普通任务示例](../tasks.md)中的 `rewards`：

```yaml
rewards:
  food:
    type: item
    item:
      material: BREAD
      amount: 8
    display:
      name: '面包 ×8'
  thanks:
    type: message
    message: '&a完成任务，辛苦了，{player}！'
```

`food` 和 `thanks` 是你起的条目 ID。领奖时两个条目都会执行，不是二选一。`type` 决定奖励类型，`display` 只改变预览文字，不改变实际发放数量。

## 奖励配置位置

| 使用位置 | 配置路径 |
| --- | --- |
| 普通任务、卷轴 | 根节点 `rewards`。 |
| 周期任务 | `task.rewards`，每项生成委托各发一份。 |
| 战令 | `levels.<等级>.free` 或 `.premium`。 |
| 里程碑 | `stages.<阶段>.rewards`。 |

| `type` | 用途 | 教程 |
| --- | --- | --- |
| `item` | 发放原版或受支持的自定义物品。 | [物品、命令和消息](items-commands.md) |
| `console_command` | 以控制台身份执行命令。 | [物品、命令和消息](items-commands.md) |
| `message` | 向领奖玩家发送消息。 | [物品、命令和消息](items-commands.md) |
| `battlepass-experience` | 增加指定战令的积分。 | [成长奖励](progression.md) |
| `random` | 从加权选项中抽取一组或多组。 | [随机奖励](random.md) |

只有这些类型可以直接作为奖励。声音、标题等是菜单[动作](../actions/README.md)，不能直接把 `type: sound` 写进奖励。

## 奖励确定与保存时机

插件会保存已经确定的奖励，避免每次打开菜单都重新抽取。

| 玩法 | 随机结果何时确定 |
| --- | --- |
| 普通任务 | 接取时。 |
| 周期委托 | 生成当期任务时。 |
| 卷轴 | 发放时保存定义，首次激活时抽取奖励。 |
| 战令等级、里程碑阶段 | 阶段解锁时。 |

重登或重载不会重抽这些结果。修改奖励后，请测试新任务、新卷轴或尚未解锁的阶段。复用配置可使用[奖励池或奖励库](pools.md)，不要与抽目标的 `pools/` 混淆。

## 领奖异常处理

领奖会先保存处理中状态，再发放奖励，最后保存结果。如果保存或发放中断，可能出现 `CLAIMING` 或 `REVIEW`。管理员应先核对物品和命令是否已执行，再处理记录。

外部命令和已经发出的物品不能随数据库操作一起撤回。把状态改回可领取可能再次发奖，不能将其当作通用的“修复按钮”。
